# Mini NPU Simulator

2차원 패턴 데이터와 필터 간의 유사도를 계산하는 **MAC(Multiply-Accumulate) 연산**을 외부 라이브러리 없이 순수 Python으로 구현한 시뮬레이터입니다.

---

## 1. 실행 방법 (macOS 기준)

1. 터미널(또는 VS Code 내장 터미널)을 열고 프로젝트 폴더로 이동합니다.
   ```bash
   cd ~/Desktop/mini_npu
   ```
2. `main.py`와 `data.json`이 같은 디렉토리에 있는지 확인한 후 실행합니다. (Python 3.8 이상 필요)
   ```bash
   python3 main.py
   ```
3. 실행 후 원하는 모드를 선택합니다.
   - `1`: **사용자 입력 (3×3)** — 필터 A, B와 패턴을 3줄씩 공백 구분으로 입력하거나 자동 생성기로 테스트합니다.
   - `2`: **data.json 분석** — `data.json`의 `size_5`, `size_13`, `size_25` 필터와 패턴을 로드하여 일괄 판정 및 성능 분석을 수행합니다.
   - `0`: **종료** — 시뮬레이터를 종료합니다.

---

## 2. 구현 요약

- **데이터 구조 (`Matrix2D`)**: $N \times N$ 크기의 2차원 리스트를 캡슐화하고 행/열 크기 일관성 및 실수(`float`) 변환을 검증합니다.
- **라벨 정규화 (`normalize_label`)**: `data.json` 내부의 이질적인 키와 기호(`'+'`, `'cross'`, `'x'`, `'X'`)를 프로그램 내부 표준 라벨인 `'Cross'`와 `'X'`로 통일하여 비교 오류를 방지했습니다.
- **MAC 연산 (`compute_mac_2d` / `compute_mac_1d`)**: 외부 라이브러리(NumPy 등) 없이 2중 `for` 루프로 동일 위치 원소의 곱셈과 누적을 구현했으며, 보너스 과제로 1차원 리스트 평탄화(`to_1d`)를 통한 단일 루프 최적화도 함께 측정했습니다.
- **허용오차 기반 비교 (`judge_scores`)**: 부동소수점 미세 오차로 인한 오판정을 막기 위해 `abs(score_a - score_b) < 1e-9`일 때 동점(`UNDECIDED`)으로 처리합니다.

---

## 3. 결과 리포트

### 3.1 실행 요약 및 실패 케이스 원인 분석
`data.json` 내 총 6개의 테스트 케이스를 실행한 결과 **통과 3개(`size_5_2`, `size_13_1`, `size_25_2`)**, **실패 3개(`size_5_1`, `size_13_2`, `size_25_1`)**가 기록되었습니다. 실패 원인을 **데이터/스키마 문제**, **로직/라벨 문제**, **수치 비교 문제**로 분리해 진단한 결과는 다음과 같습니다.

1. **데이터/스키마 및 라벨 정규화 (오류 0건)**
   - `size_5`, `size_13`, `size_25` 필터 모두 정상 로드되었으며, 필터 키(`cross`, `x`)와 `expected` 기호(`+`, `x`)를 표준 라벨(`Cross`, `X`)로 정규화함으로써 표기 불일치로 인한 오탐을 완전히 제거했습니다.
2. **수치 비교(부동소수점 및 동점 정책)로 인한 의도된 FAIL (3건)**
   - **`size_5_1`**: `Cross = 0.9`, `X = 0.8999999999999999` → 두 점수의 차이는 $1.11 \times 10^{-16}$으로, IEEE 754 부동소수점 표현 한계(기계 입실론) 수준의 미세 오차만 존재합니다.
   - **`size_13_2`**: `Cross = 7.499999999999997`, `X = 7.5` → 두 점수의 차이는 $2.66 \times 10^{-15}$으로 실질적으로 동일한 점수입니다.
   - **`size_25_1`**: `Cross = 4.9`, `X = 4.899999999999999` → 두 점수의 차이는 $1.78 \times 10^{-15}$으로 실질적으로 동일한 점수입니다.
   - **진단 결론**: 만약 단순 부등호(`score_a > score_b`)로 비교했다면 부동소수점 잔차 오차($10^{-16} \sim 10^{-15}$)에 의해 `size_5_1`은 `Cross`로, `size_13_2`는 `X`로 오판정되었을 것입니다. 허용오차(`epsilon = 1e-9`) 기준을 적용했기 때문에 세 케이스 모두 유의미한 차이가 없는 모호한 입력으로 정확히 분류되어 `UNDECIDED` 판정을 내렸으며, `expected`가 특정 패턴(`Cross` 또는 `X`)으로 고정되어 있어 `FAIL`로 집계되었습니다.

### 3.2 시간 복잡도 분석 ($O(N^2)$)
MAC 연산은 가로 $N$, 세로 $N$ 크기의 2차원 배열 내 모든 원소 쌍에 대해 곱셈 1회와 덧셈 1회를 수행하므로, 입력 크기 $N$에 대해 총 **$N^2$번**의 연산을 수행합니다. `time.perf_counter()`를 이용해 I/O 시간을 제외한 순수 연산 구간을 10회 반복 측정한 실측 결과는 다음과 같습니다.

| 크기 ($N \times N$) | 연산 횟수 ($N^2$) | $3 \times 3$ 대비 연산량 배율 | 2D 평균 시간(ms) | 1D 최적화 평균 시간(ms) |
| :--- | :---: | :---: | :---: | :---: |
| **3 × 3** | 9 | 1.00배 | 0.0010 ms | 0.0010 ms |
| **5 × 5** | 25 | 2.78배 | 0.0022 ms | 0.0014 ms |
| **13 × 13** | 169 | 18.78배 | 0.0142 ms | 0.0085 ms |
| **25 × 25** | 625 | 69.44배 | 0.0406 ms | 0.0313 ms |

- **근거**: 입력 크기 $N$이 `3`에서 `25`로 약 8.33배 증가할 때 연산 횟수는 $8.33^2 \approx 69.44$배(9회 → 625회)로 늘어나며, 2D 평균 연산 시간 역시 `0.0010 ms`에서 `0.0406 ms`로 약 40.6배 증가하여 $N^2$에 비례하는 이차(Quadratic) 증가 추세를 보입니다. (작은 $N$에서는 파이썬 함수 호출 오버헤드가 일부 포함되어 배율 차이가 완화되지만, $N$이 커질수록 $N^2$ 기울기에 수렴합니다.)
- **최적화 고찰**: 보너스 과제로 구현한 1차원 평탄화(`compute_mac_1d`)는 2중 루프 제어와 2차원 인덱스 참조(`data[r][c]`)를 단일 루프로 줄여 `13×13`에서 약 40%, `25×25`에서 약 23%의 실행 시간을 단축했습니다. 그러나 점근적 시간 복잡도는 여전히 **$O(N^2)$**이므로, 고해상도 이미지 처리를 위해서는 수천 개의 MAC 연산기를 동시에 가동하는 NPU의 병렬 아키텍처가 필수적임을 확인할 수 있습니다.
